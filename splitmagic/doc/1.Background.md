# SplitMagic Recompute Architecture Note 

## 1. Background 

### 1.1 딥러닝 학습 과정 

딥러닝 모델의 학습은 Forward 와 Backward 두 단계로 이루어진다. 

Forward 단계에서 입력 데이터를 이용하여 모델의 출력을 계산하고 최종적으로 Loss 를 생성한다. 이후 Backward 단계에서는 Loss로부터 각 연산의 Gradient 를 계산하여 모델의 파라미터를 업데이트 한다. 

이 두 과정은 독립적으로 수행되는 것이 아니라, Forward 과정에서 생성된 중간 결과들이 Backward 계산에 다시 사용된다.

### 1.2 PyTorch Autograd 

PyTorch는 Automatic Differentiation(Autograd)을 이용하여 Forward 과정에서 수행된 연산들을 기록하고, 이를 기반으로 Backward Graph를 구성한다.

Backward 단계에서는 이 Graph를 따라 각 연산의 Gradient를 계산한다.

즉, Forward 와 Backward 는 독립적인 과정이 아니라 Autograd를 통해 하나의 계산 과정으로 연결되어 있다. 


### 1.3 Saved Tensor 이란 무엇인가? 

PyTorch의 Automatic Differentiation( Autograd ) 은 Backward 를 수행하기 위해 Forward 과정에서 생성된 중간 Tensor들 중 Backward 계산에 필요한 Tensor들을 저장한다.

예를 들어 Convolution, Batch Normalization, ReLU 와 같은 연산들은 Backward를 수행할 때 Forward 에서 생성된 입력 또는 출력 Tensor를 다시 사용한다. 

이러한 Tensor를 본 문서에서는 Saved Tensor 라고 부른다. 

일반적인 환경에서는 Forward와 Backward 가 동일한 프로세스에서 수행되므로 Saved Tensor는 메모리에 그대로 유지되며 별도의 처리가 필요하지 않다. 

예시를 들자면 

```python 
import torch
import torch.nn as nn

x = torch.randn(1, 3, 32, 32)

conv = nn.Conv2d(3, 64, kernel_size=3)
relu = nn.ReLU()

y = conv(x)
z = relu(y)

loss = z.sum()
loss.backward()
```
이 예제에서 Forward 는 다음과 같은 순서로 수행된다. 

각 연산은 출력 Tensor를 생성하지만, Backward 계산을 위해 저장해야 하는 Tensor는 연산마다 서로 다르다.

```
Input (x)
      │
      ▼
Conv
      │
      ▼
y
      │
      ▼
ReLU
      │
      ▼
z
      │
      ▼
Loss
```

그러나 Backward에서는 단순히 Gradient 만 사용하는 것이 아니라, Forward에서 생성된 일부 Tensor를 다시 참조한다. 

대표적인 예는 다음과 같다 

| Operator | Backward에서 참조하는 Saved Tensor |
|----------|----------------------------------|
| Conv2d | Forward Input (`x`) |
| ReLU | Forward Output (`z`) |
| BatchNorm2d | Forward Input, Running Mean, Running Variance |

즉,

* Conv Backward는 입력 영상(x)이 필요하고,
* ReLU Backward는 출력(z)이 필요하며,
* BatchNorm Backward는 입력과 통계 정보를 함께 사용한다.

이와 같이 Backward 계산을 위해 Forward 과정에서 저장되는 Tensor를 본 문서에서는 Saved Tensor라고 부른다.

이러한 Saved Tensor는 일반적인 환경에서는 메모리에 그대로 유지되지만, Forward와 Backward가 서로 다른 노드에서 수행되는 환경에서는 별도의 관리가 필요하다.

### 1.4 Split 환경에서 발생하는 문제 

Forward Backward가 서로 다른 노드에서 수행되는 환경에서는 상황이 달라진다. 

예를 들어,

```

Node A
Forward

↓

Network

↓

Node B
Backward

```


와 같이 Forward 는 Node A에서 수행되고 Backward는 Node B에서 수행된다면, Backward에 필요한 Saved Tensor는 모두 Node A 의 메모리에 존재하게 된다

따라서 Node B 는 Gradient 를 계산하기 위해 필요한 Saved Tensor를 사용할 수 없다. 

즉 

> Forward와 Backward가 서로 다른 노드에서 수행되는 순간, Backward에 필요한 Saved Tensor를 어떻게 전달할 것인가라는 문제가 발생한다. 이 문제가 해결되지 않으면 Node B는 정상적으로 Backward를 수행할 수 없다.

### 1.5 해결해야 하는 문제 
가장 직관적인 방안은 Forward 과정에서 생성된 모든 Saved Tensor를 Node B 로 전송하는 것이다. 

이 방법은 기존 PyTorch Backward를 그대로 사용할 수 있으며 Gradient Correctness 역시 보장된다. 

그러나 Saved Tensor의 크기는 모델이 커질수록 매우 커질 수 있으며, 모든 Tensor를 그대로 전송하는것은 높은 통신 비용을 발생시킨다. 

따라서 본 연구의 목표는

> Backward 수행에 필요한 Saved Tensor의 전송량을 줄이면서도, 기존 PyTorch Backward와 동일한 Gradient를 계산할 수 있는 방법을 설계하는 것이다.

이를 위해 Forward와 Backward 사이에서 전달되는 Saved Tensor를 효율적으로 관리하는 구조를 제안한다.
