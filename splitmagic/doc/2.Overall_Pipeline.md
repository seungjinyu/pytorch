# SplitMagic Recompute Architecture Note 

## 2. Overall Pipeline

### 2.1 시스템 개요 
SplitMagic은 Forward와 Backward가 서로 다른 노드에서 수행되는 환경을 가정한다.

Node A는 Forward를 수행하고, Node B 는 Backward를 수행한다. 그러나 Backward를 수행하기 위해 필요한 Saved Tensor는 Forward 과정에서 생성되므로 기본적으로 Node A의 메모리에 존재한다. 

따라서 Node A 는 Backward 수행에 필요한 정보는 Node B로 전달해야 하며, Node B 는 이를 이용하여 기존 PyTorch Backward를 수행한다.

전체 시스템은 크게 Forward 수행, Payload 생성 및 전달, Backward 준비, Backward 수행의 단계로 구성된다.

```text
                  Node A                           Node B

Input
  │
  ▼
Forward
  │
  ▼
Capture Required Information
  │
  ▼
Generate Payload
  │
══════════════ Network ══════════════►
                                     │
                                     ▼
                              Receive Payload
                                     │
                                     ▼
                         Check Required Tensor
                                     │
                                     ▼
                         Prepare Backward
                                     │
                                     ▼
                           PyTorch Backward
                                     │
                                     ▼
                            Optimizer Step
```


### 2.2 전체 처리 과정 

전체 시스템은 크게 다섯 단계로 구성된다. 

**Step 1. Forward 수행**

Node A는 입력 데이터를 이용하여 Forward를 수행한다. 

이 과정에서 PyTorch Autograd가 Backward에서 사용할 Saved Tensor가 생성된다. 

**Step 2. Payload 생성**

Forward가 종료되면 Saved Tensor 중 필요한 Tensor를 Payload 형태로 구성한다. 

Payload는 Node A와 Node B 사이에서 전달되는 데이터이며, Backward 수행에 필요한 정보를 전달하기 위한 컨테이너 역할을 한다.

**Step 3. Payload 전달**

생성된 Payload는 Network를 통해 Node B로 전달된다.

**Step 4. Backward 준비**

Node B는 전달받은 Payload를 검사하여 Backward 수행에 필요한 Saved Tensor가 모두 존재하는지 확인한다. 

필요한 Tensor가 존재하지 않는 경우에는 해당 Tensor를 다시 계산( Recompute)하여 준비한다. 

Backward 수행을 위한 모든 Saved Tensor가 준비될 때까지 이 과정을 반복한다.

**Step 5. Backward 수행**

필요한 Saved Tensor가 모두 준비되면 기존 PyTorch Backward를 그대로 수행한다. 

이 과정에서 Gradient 가 계산되고,Optimizer 를 통해 모델의 파라미터가 업데이트 된다. 


### 2.3 각 단계의 역할

| Stage| 역할|
|-----------|-----------------------|
|Forward| 모델의 출력과 Saved Tensor 생성|
|Payload Generation| Forward 결과를 Payload 형태로 구성|
|Payload Transfer | Node A -> Node B로 Payload 전달 |
|Backward Preparation| Backward 수행에 필요한 Saved Tensor 준비|
|PyTorch Backward| Gradient 계산 및 Parameter 업데이트|


### 2.4 Summary

Overall Pipeline은 다음과 같은 흐름으로 동작한다.

1. Node A에서 Forward를 수행한다.
2. Forward 결과를 Payload 형태로 구성한다.
3. Payload를 Node B로 전달한다.
4. Node B는 Backward 수행에 필요한 정보를 준비한다.
5. 기존 PyTorch Backward를 수행하여 Gradient를 계산한다.
