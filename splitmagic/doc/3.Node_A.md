
# SplitMagic Recompute Architecture Note 

## 3.Node A 

### 3.1 Node A의 역할

Node A는 SplitMagic에서 Forward를 수행하는 노드이다.

Forward 과정에서 생성되는 Saved Tensor는 이후 Node B의 Backward 수행에 필요하므로, Node A는 단순히 Forward만 수행하는 것이 아니라 Backward 수행에 필요한 정보를 함께 수집하여 전달한다.

이를 위해 Node A는 다음과 같은 과정을 수행한다.

1. Forward를 수행한다.
2. Backward 수행에 필요한 Tensor를 수집한다.
3. 수집된 정보를 Payload 형태로 구성한다.
4. Payload를 Node B로 전달한다.

### 3.2 Entry Point 

**Location**

splitmagic/runtime.py

**Function**

capture_jin_forward_plan()

Node A의 모든 핵심 동작은 `capture_jin_forward_plan()` 함수에서 시작된다.

이 함수는 Forward 수행부터 Payload 생성까지의 전체 과정을 담당한다.

```python
def capture_jin_forward_plan(
    self,
    x,
    y,
    plan,
):
```

이 함수는 다음과 같은 순서로 동작한다.

```
capture_jin_forward_plan()
↓
Queue 생성
↓
Hook 등록
↓
Forward 수행
↓
Tensor Capture
↓
Payload 생성
↓
Return
```
### 3.3. Step 1. Build lookup queues

**Location**

splitmagic/runtime.py

**Function**

capture_jin_forward_plan()

---

#### 목적 
Forward Hook 가 실행되는 순서와 Backward 실행 계획(`plan`)의 순서를 일치시키기 위한 Lookup Queue를 생성한다.

#### 왜 Queue가 필요한가?

Node B에서 생성한 `plan`은 Backward 실행 순서를 기준으로 생성된다.

반면 Node A에서 등록한 Forward Hook은 모델의 Forward 실행 순서대로 호출된다.

따라서 동일한 Tensor를 참조하더라도 두 순서는 서로 반대가 된다.
